# PRAGAS: Enhancing Few-Shot Continual Relation Extraction via Pairwise Augmentation and Guided Sharpness-Aware Optimization

Official implementation of **PRAGAS**, published in *Artificial Intelligence*.

Hoang Thanh Dat\*, Nguyen Hoang Anh\*, Nam Le Hai, Linh Ngo Van, Sang Dinh (\* equal contribution)

**Paper:** [https://www.sciencedirect.com/science/article/abs/pii/S0004370226001712](https://www.sciencedirect.com/science/article/abs/pii/S0004370226001712)

## Overview

Few-shot Continual Relation Extraction (FCRE) has to learn new relations from a handful of examples while not forgetting old ones. PRAGAS tackles both problems with three components that plug into existing FCRE frameworks:

- **Pairwise Augmentation (PairAug).** Concatenates two memory samples into one composite sample that carries both relation labels. This enriches the training distribution with relation-preserving samples, without any external generator. It is trained with a margin loss $\mathcal{L}_{ML}$ and a contrastive loss $\mathcal{L}_{CL}$.
- **Salient Distillation.** Distills relational knowledge from the previous model on the top-$k$ most attended tokens (RKD), to preserve old relations.
- **Guided Sharpness-Aware Minimization (GuidedSAM).** Adapts the SAM perturbation radius $\rho$ to the distillation loss: when the model drifts further from old knowledge, it searches for flatter minima more aggressively.

PRAGAS is applied on top of CPL and SIRUS for FCRE, and on top of SharpSeq for Continual Event Detection (CED).

## Main Results

Accuracy (%) on all seen relations after the last task (T8) and averaged over the 8 tasks, BERT backbone, 5-shot, mean over 6 runs.

| Method | FewRel T8 | FewRel Avg | TACRED T8 | TACRED Avg |
|---|---|---|---|---|
| CPL | 65.63 | 75.53 | 52.42 | 66.60 |
| **CPL + PRAGAS** | **68.16** | **78.76** | **64.00** | **74.98** |
| SIRUS | 67.76 | 77.68 | 59.95 | 71.84 |
| **SIRUS + PRAGAS** | **70.08** | **79.93** | **69.83** | **77.55** |

Continual Event Detection, F1 (%) after the last task:

| Method | MAVEN | ACE |
|---|---|---|
| SharpSeq | 57.85 | 61.55 |
| **SharpSeq + PRAGAS** | **61.17** | **63.57** |

## Few-Shot Continual Relation Extraction (FCRE)

### Setup

```bash
cd FCRE
pip install -r requirements.txt
python -m nltk.downloader punkt wordnet
```

**OpenAI API key.** The CPL and SIRUS baselines augment the memory buffer with samples generated by `gpt-4o-mini` (`--gen 1` in CPL, `--use_augment` in SIRUS). This is part of the base frameworks, not of PRAGAS. Set your key as an environment variable, or put it in a `.env` file in the working directory:

```bash
export OPENAI_API_KEY=sk-...
```

Generation is done on the fly, so results can vary slightly between runs.

**Hugging Face token** (LLM2Vec backbones only):

```bash
export HUGGINGFACE_API_KEY=hf_...
```

### Datasets

**No data is included in this repository.** FewRel, TACRED, MAVEN and ACE 2005 are distributed under their own licenses (TACRED and ACE 2005 by the LDC), so you have to obtain them yourself:

- **FewRel**: official release by THUNLP.
- **TACRED**: Linguistic Data Consortium, catalog LDC2018T24 (LDC license required).

We follow the FCRE protocol of Qin and Joty (2022) and use the same task splits as the official CPL and SIRUS releases. Each framework (`FCRE/CPL`, `FCRE/SIRUS/BERT`, `FCRE/SIRUS/LLM`) reads its data from a local `data/` folder with this layout:

```
data/
├── CFRLFewRel/
│   ├── rel_index.npy
│   ├── relation_name.txt
│   ├── relation_description.txt
│   ├── CFRLdata_10_100_10_5/     # 5-shot:  train_0.txt, valid_0.txt, test_0.txt, rel_cluster_label_0.npy
│   └── CFRLdata_10_100_10_10/    # 10-shot: same files
└── CFRLTacred/
    ├── rel_index.npy
    ├── relation_name.txt
    ├── relation_description.txt
    ├── CFRLdata_6_100_5_5/
    └── CFRLdata_6_100_5_10/
```

`data/` is git-ignored, as are the tokenization caches (`_process_*`) the code writes there.

| Dataset | Tasks | First task | Later tasks |
|---|---|---|---|
| FewRel | 8 | 10 relations x 100 samples | 10-way 5-shot |
| TACRED | 8 | 6 relations x 100 samples | 5-way 5-shot |

Every script runs 6 rounds with different seeds and task orders, then reports the mean and standard deviation.

### Main arguments

| Argument | Paper notation | Description |
|---|---|---|
| `--mixup` | PairAug | Enable Pairwise Augmentation on the memory buffer |
| `--mixup_loss_1` | $\beta_1$ | Weight of the margin loss $\mathcal{L}_{ML}$ |
| `--mixup_loss_2` | $\beta_2$ | Weight of the contrastive loss $\mathcal{L}_{CL}$ |
| `--lambda_A` (CPL) | $\lambda_A$ | Weight of the composite-sample loss |
| `--SAM` (CPL) / `--sam` (SIRUS) | | Enable sharpness-aware minimization |
| `--sam_optimizer` | | `SAM`, `ASAM`, `ESAM`, `GCSAM`, `FriendlySAM`, `LookbehindSAM`, `LookbehindASAM` |
| `--rho` | $\rho$ | Base SAM perturbation radius |
| `--dynamic-rho` | GuidedSAM | Adapt $\rho$ from the Salient Distillation score |
| `--rho_weight` (CPL) / `--rho-weight` (SIRUS) | $\lambda_\rho$ | Scale of the adaptive perturbation radius |
| `--distill` | | Enable Salient Distillation |
| `--distill_type` | | `RKD` (paper), or `KLDivLoss` (CPL) / `KLDivAndAngleLoss` (SIRUS) |
| `--distill_top_k` | $k$ | Number of salient tokens |
| `--distill_loss_weight` | $\lambda_D$ | Weight of the distillation loss. In SIRUS the default `0` uses distillation only to drive the GuidedSAM radius |
